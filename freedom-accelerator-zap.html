3. Code by Zapier — Normalize Inputs (JavaScript)

Input Data:
rawName = {{1.user_name}}
rawEmails = {{1.email}}
txnId = {{1.transaction_id}}
paymentDate = {{1.created_at}}
const titleCase = s => s.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
const raw = (inputData.rawName || '').trim();
const parts = raw.split(/\s+/);
const firstName = parts[0] ? titleCase(parts[0]) : '';
const lastName  = parts.slice(1).length ? titleCase(parts.slice(1).join(' ')) : '';

// Whop sometimes returns multiple emails comma/semicolon separated
const email = (inputData.rawEmails || '')
  .split(/[,;\s]+/)[0]
  .toLowerCase()
  .trim();

const txnKey = `freedom_${inputData.txnId}`;

const d = new Date(inputData.paymentDate);
const monthYear = d.toLocaleDateString('en-US', { month: 'long', year: 'numeric' });

output = { firstName, lastName, email, txnKey, monthYear };

Required Airtable schema (minimum)

Payments table: Whop Transaction ID (text, unique), Client (linked), Product (single select), Amount (currency), Payment Month (text)
Clients table: First Name, Last Name, Email, Prospect Stage, Tags (multi-select), Current Product, Source, Last Payment Month
Once Payments table has a Client link + Product field, you can compute "first Freedom payment?" with a rollup/formula instead of a Find step. That's the next-level simplification.

Open questions before you build

2. What field on the Whop trigger holds the unique transaction ID? (Used for idempotency in step 4.)
3. Do you want one Slack channel for all Freedom events, or separate channels per outcome (new / upgrade / rebill)?
4. Should rebills also send a "thanks for renewing" email, or stay silent like the current draft?
